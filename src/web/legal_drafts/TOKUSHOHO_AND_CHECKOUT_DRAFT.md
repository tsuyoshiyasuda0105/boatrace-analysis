## 2. Stripe決済直前の最終確認画面

決済ボタンの直前に、利用者がスクロールせず又は容易な操作で、少なくとも次を確認できるようにします。

### 表示例

```text
[プラン名]

料金: 月額 [○○円]（税込）
提供内容: [バックテスト○回/日、条件保存○件、会員限定Discord等]
利用開始: 決済完了後すぐ
契約期間: 1か月
自動更新: あり
次回請求日: [具体的な日付]

解約:
アカウント画面からいつでも手続できます。
[次回請求日の前日○時]までに解約すると、次回以降の請求はありません。
解約後も現在の契約期間終了日まで利用できます。

返金:
[確定した返金条件を平易に表示]

注意:
本サービスは過去データの分析ツールです。
将来の的中又は利益を保証しません。

[ ] 利用規約、プライバシーポリシー及び特定商取引法に基づく表記を確認し、同意します。

[月額○○円で申し込む]
```

## 3. 決済画面の実装要件

1. 「申し込む」ボタンに、支払が発生することが分かる文言を使用する。
2. 無料期間がある場合、課金開始日、終了後の料金、自動更新及び解約期限をボタン直前に表示する。
3. 初回価格と更新価格が異なる場合、両方を同じ画面で表示する。
4. 年額プランは、年額総額を月額換算より目立つ又は同等の位置で表示する。
5. 利用回数又は機能制限がある場合、申込み前に明示する。
6. 解約方法を「問い合わせ」だけにせず、実際に利用可能な手順と画面名を表示する。
7. 返金なしの場合でも、法令上必要な返金まで排除する表現を使用しない。
8. 利用規約、プライバシーポリシー、特商法表記へのリンクを設置する。
9. 同意日時、規約バージョン、表示した価格・プラン、StripeセッションID及びユーザーIDを記録する。
10. 決済完了後、料金、契約期間、次回請求日、解約方法及び領収情報をメール又はアカウント画面で確認できるようにする。
11. Stripe Webhookの署名を検証し、同一イベントを重複処理しない。
12. 支払失敗、解約、返金及びプラン変更時の権限反映ルールを定める。

## 4. 申込み前に確定が必要な経営判断

- 月額又は年額の料金
- 税込表示とインボイス対応の要否
- 無料期間を設けるか
- ベータ会員を自動課金へ移行するか、改めて申込みを求めるか
- 解約の適用時期
- 日割り返金の有無
- 当方都合の長期停止又は終了時の返金
- 支払失敗後の猶予期間
- Discord参加権限が停止される時点
- 保存した条件及び投稿が退会後に残る期間
- 料金変更時の既存会員への適用時期

ベータ会員を本人の明示的な申込みなしに有料へ移行させない設計を推奨します。

## 5. 公開前チェック

- [ ] 事業者名、責任者、所在地、電話番号、メールアドレスが事実と一致する
- [ ] 税込価格、請求周期、契約期間、自動更新が明記されている
- [ ] 無料期間終了後の課金条件が明記されている
- [ ] 解約手順を実機で最後まで確認した
- [ ] 解約してもアプリ削除だけでは契約解除にならない旨を案内した
- [ ] 返金、重複請求、障害時の扱いを決めた
- [ ] 決済完了メール又は契約画面で次回請求日を確認できる
- [ ] プラン変更、支払失敗、返金、チャージバックの権限処理をテストした
- [ ] 利用規約とプライバシーポリシーの同意ログが残る
- [ ] 20歳以上の利用条件を登録及び申込画面に表示した
- [ ] 的中・利益保証ではないことを表示した
- [ ] BOAT RACE関連データの取得、表示及び商用利用条件を確認した
- [ ] 日本法に詳しい専門家の確認を受けた
