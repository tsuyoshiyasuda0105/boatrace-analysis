## サマリ表記ルール

- 見出しは設定された条件 JSON の項目数を `検索条件（N項目）` と表示する。`fast` は計算方式であり絞り込み条件ではないため数えない。
- 艇別条件は各艇のプロパティを1項目、比較条件は各比較行を1項目、開始日と終了日はそれぞれ1項目として数える。
- 条件がない場合は `検索条件: 指定なし（全レース）` と表示する。
- 条件は `[レース]`、`[番組]`、`[艇別]`、`[比較]`、`[期間]` に分類し、未指定の分類・項目は表示しない。条件が1件以上あり期間指定がない場合は `[期間] 全期間` と表示する。
- 会場名と買い目名は既存の select option、決まり手と比較指標は既存のクライアント定義、各入力名は既存 DOM ラベルから取得し、名称マスタを二重定義しない。
- 買い目は `単勝 1`、`2連単 1-3`、`3連単 1-2-3` の形式。複数値は `・`、同一分類内の条件は `／` で区切る。
- 数値条件は勝率・事故点=`点`、モーター・2連対率・事故率=`%`、ST・展示タイム=`秒`、年齢=`歳`、事故件数=`件`、展示順位=`位` を付け、min=`以上`、max=`以下`、両端指定=`下限〜上限` とする。
- 級別は `A1・A2`、選手は送信文字列の先頭の選手番号を `選手: 4320` と表示する。
- 艇間比較は検索エンジンの差分定義に合わせ、ge を `N号艇の指標 ≥ M号艇 +X単位`、le を `N号艇の指標 ≤ M号艇 −X単位` と表示する。
- 全ての動的文字列を HTML エスケープしてから描画する。

## マイ手法との統一状況

現行のマイ手法カードは手法名、保存日、探索時・全期間・フォワード成績、判定だけを表示しており、条件本文は表示していない。重複している条件表記はないため、Step 16 では検索結果のみを変更した。将来カードへ条件を追加する場合は、今回の同一フォーマッターを利用できる構成になっている。

## 既知の制限

- 期間は日付入力の精度を保つため `YYYY-MM-DD` で表示する。
- マイ手法カードには現在条件本文がないため、保存済み条件のサマリ表示は今回の対象外。
- pytest が作成した一時ディレクトリの1つは Windows ACL により通常権限で削除できず、記録済みの厳密なパスだけを昇格して削除した。製品データは含まれない。

DB の書込み、ネットワーク、スケジューラ、デプロイ、push は実施していない。E2E の既存 fixture によるローカル検索 DB の読み取り以外に DB 接続は行っていない。
