## 実装内容

### 1. 3連単オッズ条件

- `odds_snapshot` を独立テーブルとして追加し、`asof_race_features` のスキーマ・行は変更していない。
- `--sync-odds --date-from ... --date-to ...` を追加した。通常実行は append-only（既存主キーをスキップ）、`--rebuild` は指定期間のオッズだけを入れ替える。
- T-5min/final ごとに、同一レース・買い目の最新 `recorded_at` を同期する。
- 条件指定時だけ `odds_snapshot` を買い目・snapshotで `LEFT JOIN` し、min/max は包含境界で判定する。
- オッズ行なしはバックテストでは `condition_null`、当日照合では `pending` / `undetermined_columns=["odds"]` とする。
- 単勝・2連単でオッズ条件を指定すると「オッズ条件は現在3連単のみ対応しています（単勝・2連単のオッズは未収集）」を返す。

### 2. 艇間比較UI

- 表示を「N号艇の 指標 が M号艇 以上/以下（差: 任意）」へ変更した。
- 差の空欄は `margin=0` として扱い、純粋な `>=` / `<=` を組める。
- APIでも margin 省略を0として扱う。既存の margin 付き保存手法は同じJSON契約で継続利用できる。

### 3. 動線再設計

| 変更前 | 変更後 |
|---|---|
| 検索ボタンは長い条件フォーム末尾、保存ボタンは結果内 | 画面下の不透過スティッキーバーに検索・保存・リセットを集約 |
| 設定条件数を全体で確認できない | バーに「条件 N個」を常時表示 |
| 直近結果を見直すには結果位置へ戻る必要 | バーに回収率/NのミニKPIを表示し、クリックで結果へ移動 |
| デスクトップで条件編集時に結果が画面外へ流れる | 881px以上で右結果パネルが追従 |
| モバイル検索後も元のスクロール位置 | 検索成功後に結果へ自動スクロール（reduced-motion時は即時移動） |
| 結果更新が視覚的に分かりにくい | テーマ対応の短い更新ハイライトを追加 |

スティッキーバー分の本文下padding、ダーク/ライト双方の背景・境界、検索中スピナー、二重送信抑止を実装した。
