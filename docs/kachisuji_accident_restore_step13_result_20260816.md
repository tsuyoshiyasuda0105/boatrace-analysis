## 結論

- 公式K成績ファイルから、事故イベントと全出走を `data/kachisuji_search.db` の新規テーブル `accident_events` / `racer_starts` へ復元できるようにした。

- 全期間復元は実行していない。2016-06-01〜2016-12-31 のサンプルだけを復元した。2016-06-01〜全期間の復元と feature 再生成はリンが実行する。

## 既存パーサ再利用の判断

`src/parsers/official_k.py` は部分再利用したが、事故履歴の単独パーサとしては再利用不可と判断した。

再利用したもの:

- `parse_k_text` による既存のKファイル全体解釈とパース件数の照合
- 既存の会場名、レース番号、結果行判定ヘルパー
- 既存パーサが返す `remarks` の意味と行構造

そのまま使えなかった根拠:

- `F` 行は着順欄では受理するが、ST欄の `F0.02` を後段正規表現が受理せず行全体を落とす。
- `L0/L1` は着順正規表現が直接受理しない。
- 実測では `F/L0/L1/K0/K1` が既存パーサから欠落した。2016年サンプルでは177,948行中876行が該当した。
- Kファイルの機械可読な会場制御行 `NNKBGN` を既存パーサは使わないため、`K160613.TXT` では丸亀ブロックが尼崎の race_id と衝突した。

このため、全体パースの車輪は作り直さず、公式固定幅の先頭3項目（着順2桁、艇番、登録番号）と `NNKBGN` だけを補助経路で読む。既存フル行パーサが受理しなかった行数は `fallback_rows` として必ず報告する。

## 事故コード分類

根拠は `scripts/rebuild_racer_accident_stats.py` の `DEFAULT_POINT_RULES` と `score_event`。同実装は K1/S1/S2 を racer-responsible、K0/S0 を non-responsible と明記している。

| コード | is_accident | 判断 |
|---|---:|---|
| F | 1 | フライング。既存実装の F/L 分類に従う |
| L / L0 / L1 | 1 | 出遅れ。既存実装の F/L 分類に従う |
| K1 | 1 | 既存実装で選手責任の欠場 |
| S1 | 1 | 既存実装で選手責任の失格 |
| S2 | 1 | 既存実装で妨害失格 |
| K0 | 0 | 既存実装で選手責任外の欠場 |
| S0 | 0 | 既存実装で選手責任外の失格 |
| その他（実測 `00`） | 0 | リポジトリ内に責任分類根拠がないため未分類。原文保存し事故件数へ混ぜない |

仕様書の「K0/K1は事故として数える想定」より、リポジトリ内の明示的な責任区分を優先し、K0は数えていない。

## 事故点の扱い

事故点は付与していない。

リポジトリには再構成ルールがあるが、`RULE_VERSION=official_table_2025_05_reconstructed_v2`、`applies_from=2025-05-01` であり、スクリプト自身も公式事故率フィードではないと明記している。これを2016年まで遡及する根拠はない。またStep 13指定テーブルにも事故点列はない。したがって推測による点数は作らず、原文コード、責任区分、件数、種別内訳だけを復元した。既存の `bN_accident_points` は変更していない。

## as-of定義

新事故率は次の式である。

`審査期開始日以上、対象レース日未満の選手責任事故件数 / 同範囲の出走数 * 100`

- 審査期は既存 `_accident_period_start_for_date` を再利用し、5/1〜10/31、11/1〜翌4/30。
- 対象レース日はSQL読込と二分探索の両方で排他的上限とした。当日・将来事故は含まれない。
- 出走0は NULL。0%にはしない。件数と出走数は0。
- 既存 `bN_accident_rate` は期中で利用できる最新の期末/途中スナップショットを選ぶROI互換値。新 `bN_accident_rate_period` はレースごとに前日締めで再計算するため、期中でも値が入り、未来漏洩を起こさない。
