# 勝ち筋サーチ Step 21 結果 — 級別構成の再設計とUI一致

実施日: 2026-08-17

## 実装結果

`class_mix` を、前日までに確定している番組表 `race_entries.class_number` の6艇分だけから判定する、次の排他的かつ全網羅な4区分へ変更した。6艇が揃わない、または1艇でも級別が欠測している場合は `NULL` とする。

| データ値 | 定義 |
|---|---|
| `1号艇A1・単騎` | 1号艇がA1で、A1はその1艇だけ |
| `1号艇A1・複数` | 1号艇がA1で、他にもA1がいる |
| `1号艇非A1・A1あり` | 1号艇はA1でなく、他艇にA1がいる |
| `A1なし` | 6艇にA1がいない |

生成行の `schema_version` は10へ更新した。検索側は既存のschema 2〜9を維持しつつschema 10も読めるため、移行中の旧行を失わない。

## as-of確認

級別構成は従来どおり番組表の `race_entries` から作る。`race_previews` や当日結果を級別判定へ渡していない。対象日の `asof_date` は前日であり、当日情報を使う経路は追加していない。

## 旧区分からの対応

| 旧区分 | 新区分 |
|---|---|
| `1号艇A1` | A1人数が1人なら `1号艇A1・単騎`、2人以上なら `1号艇A1・複数` に分割 |
| `A1単騎` | `1号艇非A1・A1あり`（旧値は「1号艇以外に単独A1」の意味だった） |
| `A1複数_1号艇非A1` | `1号艇非A1・A1あり` に統合 |
| `A1なし` | `A1なし` |
| `NULL` | `NULL` |

限定サンプルの旧件数でも、旧 `1号艇A1` 8,799件が新しい単騎2,715件＋複数6,084件へ分かれ、旧 `A1単騎` 8,786件＋旧 `A1複数_1号艇非A1` 3,123件が新 `1号艇非A1・A1あり` 11,909件に一致した。

## UIとの1対1一致

級別構成の選択肢valueは、指定なしを除き次の4値だけにした。

1. `1号艇A1・単騎`
2. `1号艇A1・複数`
3. `1号艇非A1・A1あり`
4. `A1なし`

データ値と順序を含めた完全一致をテストし、旧phantom `A1が2人以上`、旧 `A1単騎`、曖昧な旧 `1号艇A1` のvalueがHTMLから消えたことも確認した。

## サンプル再生成と4分類分布

`data/kachisuji_search.db` の2023-01-01〜2023-06-30だけを再生成した。途中で1レースが一時的なSQLiteロックによりスキップされたため、2023-01-01だけを再実行して補完した。最終的に対象期間は28,212行すべてschema v10となった。37件の既存結果・払戻不足警告は過去データの完全性に由来し、級別判定とは無関係である。

| class_mix | 行数 | 固定3連単の実検索 n |
|---|---:|---:|
| `1号艇A1・単騎` | 2,715 | 2,692 |
| `1号艇A1・複数` | 6,084 | 6,011 |
| `1号艇非A1・A1あり` | 11,909 | 11,815 |
| `A1なし` | 6,178 | 6,128 |
| `NULL` | 1,326 | 条件判定不能として除外 |

4つのUI値はすべて実データ検索で `n > 0` となった。行数と検索nの差は、選択した固定3連単の結果JSONが欠けるレースを検索分母から除外する既存仕様による。

検証結果は `PRAGMA quick_check=ok`、固定乱数200行で `chronology_errors=0`、`mismatches=0`。保護対象 `data/boatrace.db` は前後ともサイズ10,369,622,016 bytes、mtime ns `1786896212419668900`、races 557,785件、race_results 3,272,225件で不変だった。

なお検証中、別プロセスによる全期間再生成と見られる検索DB全体の更新が並行していたため、全体件数ではなく上記日付範囲を読み取りトランザクションで固定して集計した。そのプロセスは停止・変更していない。
