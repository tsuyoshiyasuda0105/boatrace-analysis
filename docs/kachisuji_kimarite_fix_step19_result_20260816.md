# 勝ち筋サーチ Step 19 結果 — 決まり手率の進入コース基準化

実施日: 2026-08-16

## 結論

`bN_kimarite_rate_{key}` を全出走分母から実際の進入コース分母へ変更し、`schema_version=8` とした。進入コースは既存の公式K成績ファイル共通パース経路が保存した `kachisuji_search.db.start_timing_events.course_number`、勝利決まり手は読み取り専用の `boatrace.db.race_results.kimarite` を使用する。成績ファイルの再パースは追加していない。

2023-01-01〜2023-06-30 の28,212レースだけをサンプル再生成した結果、A1級1号艇の逃げ率は平均65.64%、中央値66.13%となり、想定される55〜75%帯に収まった。現行定義の同じサンプルでの平均15.39%、最大27.78%、65%以上0件という症状を解消した。

## 採用した分母定義

- `nige`: 実進入1コースの回数を分母とし、そのうち逃げで1着になった回数を分子とする。
- `sashi` / `makuri` / `makurizashi`: 実進入2〜6コースの回数を分母とし、そのうち当該決まり手で1着になった回数を分子とする。
- `nuki` / `megumare`: どのコースでも起こりうるため、実進入1〜6コースの回数を分母とし、そのうち当該決まり手で1着になった回数を分子とする。
- `course_number` がNULLまたは1〜6外の行は分母にも分子にも入れない。
- 分子は `finishing_position=1` の `race_results.kimarite` だけを採用する。
- 有効進入回数は既存の率カラム追加を避け、prefix sum内部で保持する。`bN_kimarite_n_*` カラムは追加していない。

## 窓定義とas-ofの担保

現行の決まり手集計と同じ、前日までの365日包含窓を踏襲した。対象レース日を `D` とすると、対象範囲は `[D-365日, D-1日]`、実装上は `asof_date=D-1日` と `[asof_date-364日, asof_date]` の両端包含である。

バッチ全体のローダー上限も最終対象日の前日とし、各行では日付prefix sumを `asof_date` までで切る。対象レース当日および未来日の `start_timing_events` と `race_results` を追加した合成テストでも5走3逃げの60%が変化しないことを確認した。サンプル実DBの `verify` は28,212行中固定乱数200件を再計算し、`chronology_errors=0`、`mismatches=0` だった。

## 有効進入の閾値

閾値は5回とした。有効進入が5回未満、0回、または選手履歴が存在しない場合は0ではなくNULLとする。仕様の合成受入例「1コース5走中3回逃げ勝ち=60%」を満たしつつ、4回以下の母数を除外する。サンプルのA1級1号艇では全8,799行が5回以上で、逃げ率NULLは0件だった。

## サンプル実データ検証

対象: `asof_race_features.race_date` が2023-01-01〜2023-06-30、`b1_class='A1'` の8,799行。

| 指標 | 結果 |
|---|---:|
| 非NULL / NULL | 8,799 / 0 |
| NULL率 | 0.00% |
| 平均 | 65.64% |
| 最小 / P10 | 33.33% / 53.70% |
| P25 / 中央値 / P75 | 59.26% / 66.13% / 72.22% |
| P90 / 最大 | 77.42% / 90.00% |
| 55〜75%内 | 6,353件（72.2%） |

UIの既存決まり手利用開始日である2023-05-01〜2023-06-30に限定すると、A1級1号艇2,951件中、逃げ率65%以上は1,568件だった。実際の読み取り専用検索では結果欠損16件を除く `n=1,552` が評価対象となった。したがってユーザー症状の「65%以上で0件」は解消されている。

サンプル再生成は28,212行をすべてschema v8へ置換し、期間外529,405行は変更せずschema v7のまま保持した。検索側はv2〜v8を読み取り可能にしている。全体行数557,617は前後不変、`PRAGMA quick_check=ok`。

## データ保護と既知の制限

- `boatrace.db` はURI `mode=ro` と `PRAGMA query_only=ON` でのみ参照した。前後でサイズ10,365,227,008 bytes、mtime ns `1786880192161597500`、races 557,617件、race_results 3,270,776件が不変だった。
- `data/raw/results/` は既存の復元済み `start_timing_events` を利用したため、読み書き・再パースとも行っていない。
- サンプル再生成では既存の結果/払戻欠損により37警告が出たが、28,212行は全件挿入された。これは決まり手率計算の警告ではなく、`verify`不一致やDB破損もない。
- 決まり手率のUI利用開始日は既存どおり2023-05-01。履歴に有効進入があっても、決まり手ラベル欠損は勝利分子に加算されない。
- 今回はサンプル期間だけをschema v8へ再生成した。全557,617行の再生成はリンが別途実行する必要がある。
