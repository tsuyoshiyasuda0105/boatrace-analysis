# PROMO_STRATEGY_HANDOFF.md — プロモーション戦略の実装引き継ぎ（Codex向け）

作成: 2026-09-04 / 作成者: リン（Claude）/ 依頼者: リッキーさん
目的: 「検証屋の勝ち筋」戦略を、動画パイプラインに**実装できる仕様**として渡す。
背景・根拠の全文は提案書（Claude Artifact「検証屋の勝ち筋」）。ここは実装に必要な事だけ。

> **前提**: 声の切替とエンディングは **Codex が既に実装済み**。それらは上書きせず、
> 本書の「柱→声」「柱→オープニング」のマッピングをその仕組みに接続すること。

---

## 0. 戦略の要約（実装者が迷ったときの判断軸）

1. **立ち位置**: 予想を売らない「検証屋」。断定・的中保証・「稼げる」表現は**禁止**。
2. **AIの役割**: オープニング／演出／CM背景のみ。**数字パートは自作スライド**（実測値）。
3. **量産に見せない**: YouTube 2026-07 ポリシー対策。同じ声・同じテンポ・同型連投を避ける。
4. **締めは固定**: 「この数字、自分で確かめられます（無料）」→ 登録導線。

|----|----|-----:|------|----------|

## 3. 柱 → オープニング系統（AI映像はここに集中）

各柱に**専用のオープニング（3〜5秒）**を1系統ずつ用意し、同型連投を避ける。

| 柱 | オープニング系統 | 素材 |
|----|------------------|------|
| P1 | `op_event`: 大会名＋会場ロゴ風タイポ＋水面の迫力映像 | MiniMax H3 生成（cut1/cut5 系の水面） |
| P2 | `op_paradox`: 「〇〇は本当か？」を大きく、背景は人混み/オッズ板のイメージ | MiniMax H3 |
| P3 | `op_request`: 手紙/DM が届く演出 →「〇〇さんからのリクエスト」 | Pillow で自作可（AI不要） |
| P4 | `op_theory`: 「よく聞く話」を引用符付きで提示 → 検証へ | Pillow 自作 |
| P5 | `op_racer`: 既存の選手リール冒頭（変更なし） | 既存 |

実装案: `make_reels_netacho.py` に `OPENINGS = {"op_event": fn, ...}` を追加し、
各 `make_reel_*.py` が `PILLAR = "P1"` を宣言 → `pillar_config(PILLAR)` で
`{voice, opening, ending}` を解決する。エンディングは Codex 実装をそのまま呼ぶ。

## 4. 投稿ローテーション（同型連投の禁止）

- 週7本なら例: `P1 → P3 → P2 → P1 → P4 → P3 → P2`。**同じ柱を2日連続で出さない。**
- 月1本は**長尺（講義 lecture01 型・3〜4分）**を必ず入れる（Shorts だけのチャンネルは薄いと判定されやすい）。
- 実装案: `tools/plan_week.py` — 柱配分と直近履歴から翌週の柱列を出力（CSV/MD）。
  履歴は `out/posting_log.csv`（日付, 柱, ファイル名, 声, プラットフォーム, 再生数は後追記）。

## 5. 台本ルール（全柱共通・自動チェック可能なものはチェックを入れる）

1. **「人の視点」を1文**必ず入れる: 「私はこう見る」「ここが意外だった」「正直、驚いた」など。
   → `NARR` に `("view", "...")` キーを必須化。無ければビルドを止める。
2. **禁止語**: 「絶対」「必ず当たる」「稼げる」「勝てる（断定形）」「保証」。
   → ビルド前に台本を grep し、含まれていたら失敗させる。疑問形（「本当に勝てますか？」）は可。
3. **必須の但し書き**（エンディングに固定）: 「※的中・利益を保証するものではありません」「舟券の購入は20歳になってから」。
4. **数字は実測のみ**: `data/kachisuji_search.db` 由来。誇張・丸め方向の恣意は禁止。n（件数）を併記。
5. **選手名には必ず「選手」**を付ける。特定の予想サイト名・個人名の批判は書かない。
6. **CTA は固定文**: 「この数字、自分で確かめられます。無料です。」（「近日公開」は廃止）。

## 6. 公開時のメタ情報（プラットフォーム対策）

- **AI映像を使った回は「改変または合成コンテンツ」ラベルを付ける**（YouTube）。再生・収益に不利なし。
  → 実装案: ビルド時に `uses_ai_footage: true/false` を `out/<name>.meta.json` に書き出し、投稿担当が参照。
- 概要欄は定型（`scripts/beta_announce_texts.md` §3）。固定コメントに登録リンク。
- 配信先: YouTube Shorts（主）／Instagram Reels／**TikTok（新規開設）**／X（数字1枚画像）／note（週1）。
  同一 mp4 をそのまま流用。TikTok も 1080x1920/30fps でそのまま可。

## 7. 計測と自動判断（リンが週次で回す。Codex はログ出力を用意）

- `out/posting_log.csv` に投稿ごとの `date, pillar, file, voice, platform, views_7d` を記録。
  views は投稿7日後に手動 or API で追記。
- 判断ルール: **柱の平均再生が全体平均を2週連続で下回ったら配分を半分に**。上回れば増やす。
- あわせて登録数（本番 `profiles`）と Cloudflare 流入（`scripts/cf_access_report.py`）を投稿日と突き合わせる。

## 8. Codex への具体的な作業依頼（優先順）

1. **`pillar_config()`** を `make_reels_netacho.py` に実装し、`PILLAR` 宣言だけで
   声（既存の切替機構）・オープニング・エンディング（既存）が決まるようにする。
2. **オープニング3系統**（`op_event` / `op_paradox` / `op_request`）を実装。AI映像は
   `C:\Users\tsuyo\Downloads\cut*_1080x1920.mp4` 系を素材に、無ければ Pillow 生成でフォールバック。
3. **台本チェッカー** `tools/check_script.py`: `view` キー必須・禁止語・「選手」付与・但し書き有無を検査。
   各 `make_reel_*.py` の `md` ステージから呼ぶ。
4. **`out/<name>.meta.json` と `out/posting_log.csv`** の書き出し（§6, §7）。
5. **`tools/plan_week.py`**（§4）。
6. 既存リール（`make_reel_*.py` 30本超）に `PILLAR` を後付け。P5 は Keita のまま変更不要。

やらないこと: 声・エンディングの再実装（Codex 実装済み）、Gemini の大量呼び出し（従量課金）、
特定サイト・個人を名指しする台本。
