## 現状 (リン調査済み)

`src/web/app.py` の `throttle_guest_requests` (7136行付近) に既に IP 単位の
レート制限がある。新規実装は不要で、調整と補強が要件。
- 現状: `BOATRACE_GUEST_RATE_LIMIT` 既定 **120回/60秒**、会員は対象外、
  `/healthz` と `/static/` は除外
- 制限超過時: 429 + Retry-After + JSON

## やること

### [必須1] 既定値を公開前提に引き下げる
120回/分は公開前提だと緩い。**既定を 40回/60秒**にする (環境変数で上書き可能な
現在の設計は維持)。人間の閲覧には十分で、機械的な大量取得は抑えられる水準。
根拠を作業ログに記載すること。

### [必須2] 制限の粒度を用途で分ける
一律だと「ページ閲覧」と「API 連打」が同じ扱いになる。少なくとも2段階にする:
- 通常ページ (レース一覧・レース詳細など): 上記の既定
- `/api/` 配下: より厳しい既定 (**15回/60秒**を提案)
環境変数名は既存の命名に合わせ、`BOATRACE_GUEST_API_RATE_LIMIT` 等を新設。

### [必須3] 429 応答をブラウザ向けに整える
現在は JSON を返すため、ブラウザ閲覧者には意味不明な画面になる。
`Accept` ヘッダが HTML を求めている場合は、既存の degraded 作法
(`error_temporary.html` / `race_preparing.html` と同系統) で
「アクセスが集中しています。しばらくお待ちください」の HTML を返す。
API 経路 (`/api/`) は従来どおり JSON のまま。

### [必須4] 検索エンジンに載せない
公開後に外部から大量アクセスが来ないよう `robots.txt` を追加し、全クローラを
Disallow する。販売開始時に外せるよう、**環境変数で切替可能**にする
(`BOATRACE_ALLOW_INDEXING=1` で許可、既定は不許可)。
`/robots.txt` は認証不要・レート制限の対象外にすること。

### [必須5] 回帰テスト
- 既定値 (通常40 / API15) が入っていること
- 会員は制限対象外のままであること
- HTML 要求時は HTML、API は JSON で 429 を返すこと
- `/robots.txt` が既定で Disallow を返し、環境変数で切り替わること
- `/healthz` と `/static/` が引き続き除外されていること
