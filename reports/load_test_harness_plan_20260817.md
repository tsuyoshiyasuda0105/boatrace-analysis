## 背景と狙い

外部公開に向けて「複数同時アクセスに何人まで耐えられるか」を知りたい。
本番構成: **gunicorn 1 worker × 4 threads × 2 インスタンス = 同時8スロット**、
DB プール 12/インスタンス。想定の限界は同時8〜16接続あたり。

## 絶対ルール (本番を壊さない・実会員に配慮)

1. **origin/main へ push 禁止** (ローカル main まで)。
2. **本番アプリを実際に落とさない**。負荷テストは以下を必須で実装:
   - **読み取り専用 (GET のみ)**。POST/投稿/削除/購入等は一切叩かない。
   - **段階的ランプ** (例: 同時 2→5→10→20→40→80) を**設定可能**に。各段は短時間 (例 20〜30秒)。
   - **自動停止 (サーキットブレーカー)**: ある段でエラー率が閾値超 (既定 10%) or
     p95 レイテンシが閾値超 (既定 15秒) になったら**即座にランプを止める**。
     これ以上負荷を上げない。**本番を落とす前に自分で止まる**設計。
   - **同時数の上限キャップ** (既定 100 など)。無制限に増やさない。
   - **`/login` へのパスワード総当たりをしない** (認証は1回だけ、成功したセッションを再利用)。
3. スクレイピングではないので外部会場サイトは叩かない (本番 web のみ)。
4. `pytest tests/ -q --ignore=tests/e2e --ignore=tests/round3_e2e` を割らない (ハーネスの
   単体ロジックは軽くテスト)。
5. 作業ログ `reports/load_test_harness_work_log_20260817.md`。コミット1〜2個。
6. **本番への本格ランプは、このハーネスをリンが安全確認した後に、監視付きで実行する。**
   Codex は**ハーネス構築 + 軽いスモーク (同時≤5・短時間・/healthz 中心) の検証まで**。
   本格的な高同時数ランプは自動実行しない。

## やること

### 1. 負荷テストハーネス `scripts/load_test.py` を作る

- 非同期 (asyncio + httpx か aiohttp。requirements にあるものを優先、無ければ最小追加)。
- **設定 (引数/ env)**:
  - `--base-url` (既定 `https://boatrace-web.onrender.com`)
  - `--stages` (同時数の段。既定 `2,5,10,20,40`)
  - `--stage-seconds` (各段の秒数。既定 25)
  - `--max-concurrency` (上限キャップ。既定 100)
  - `--error-rate-stop` (既定 0.10)、`--p95-stop-sec` (既定 15)
  - `--auth` (on/off)。on なら env `BOATRACE_MEMBER_PASSWORD` で1回ログイン
    (CSRF トークン取得 → POST /login → セッション cookie 取得) し、以後 cookie を全リクエストで再利用。
    **パスワードはコードに書かない。env のみ。未設定なら auth off に自動フォールバックし、
    公開エンドポイントのみ測定する旨をログに出す。**
- **叩くエンドポイント (GET, 代表的な mix)**:
  - 公開: `/healthz`
  - 認証時: `/races?date=<today>`、`/race/<今日の実在 race_id>`、
    `/api/market-signals?date=<today>` (人間リクエストなので recompute しない=軽い想定)
  - **race_id は本番 races から実在する当日 ID を1〜数件選ぶ** (存在しない ID を叩かない)。
- **計測 (段ごと)**: リクエスト数、成功/失敗、エラー率、
  p50/p95/p99 レイテンシ、スループット (req/s)、HTTP ステータス内訳。
- **自動停止**: 上記閾値超で即停止し、「どの同時数で壊れ始めたか (knee)」を記録。
- **レポート**: `reports/load_test_result_<timestamp>.json` と、人間可読サマリを stdout。
  段ごとの表 + 「安全に捌けた最大同時数」「knee」「ボトルネック仮説」を出す。

### 2. 軽いスモーク検証のみ実行 (本格ランプはしない)

- `--stages 2,5 --stage-seconds 10 --base-url https://boatrace-web.onrender.com`
  で `/healthz` 中心の**軽いスモーク**を1回だけ実行し、ハーネスが動くこと (計測・停止・レポート)
  を確認。**本番に実害が出ない範囲**に留める。結果を作業ログに貼る。
- **高同時数ランプ (20+) はここでは実行しない**。リンが安全確認後に監視付きで回す。
