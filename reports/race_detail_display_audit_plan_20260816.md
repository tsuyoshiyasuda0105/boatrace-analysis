## 背景 (リンが公式サイト・DB・キャッシュを三点照合して切り分け済み)

会員から「各会場の天候・風が表示されない」「戸田2Rの展示情報が入っていない」との報告。
調査結果:

1. **データ収集は正常**。例: 戸田2R (`20260816-02-02`) は `race_previews` に
   展示タイム(6.66/6.64/6.73/6.70/6.83/6.72)・チルト・スタート展示ST・
   天候(曇=weather_number 2)・気温27.0・水温27.0・風速1・波高1 が**公式サイトと完全一致**で
   保存済み (live_updated_at=11:05 JST)。
2. **「発走が先の会場が空欄」は公式サイトも同じ**。直前情報は発走~1時間前まで公開されない。
   → これはバグではない。**"全会場に今すぐ天候"は不可能** (公式にも無い)。この点は
   仕様として扱い、修正対象にしない。
3. **本当のバグ = 表示/キャッシュ**。戸田2Rのキャッシュ済みレース詳細ページ HTML には
   展示タイム(6.66等)と「曇」は入っているが、**「風速」「水温」を含む水面コンディション欄
   (`race.html` の compat_analysis.water ブロック, 226-231行) が欠落**している。
   原因の疑い: レース詳細キャッシュが**朝(06:40)に生成**され、その後 11:05 に直前データが
   到着しても、**再生成が不完全** (天候/水面コンディションのセクションが埋まらない、
   または tags/compat_analysis の再計算が漏れている)。

## ゴール

**直前情報(展示タイム・チルト・スタート展示ST・天候・気温・風速・風向・水温・波高)が
DBに存在するのに、レース詳細/トップに表示されない状態をなくす。**
データ到着後は速やかに・完全にキャッシュへ反映されること。

## 絶対ルール

1. **origin/main へ push 禁止** (ローカル main まで)。
2. ROI 戦略・予測ロジック・DB スキーマ・render.yaml は変更しない。
   **スクレイピング頻度・収集ロジックは変えない** (収集は正常なので触らない)。
3. `pytest tests/ -q --ignore=tests/e2e --ignore=tests/round3_e2e` を割らない + 新規 green。
4. 作業ログ `reports/race_detail_display_audit_work_log_20260816.md`。コミット2〜4個。

## やること

### 1. 表示項目の突き合わせ (公式サイト vs アプリ)

公式 直前情報ページ (`boatrace.jp/owpc/pc/race/beforeinfo`) が持つ項目を基準に、
アプリのレース詳細が**データがある時に全て表示するか**を確認し、欠落を洗い出す:

| 公式の項目 | DB 列 (race_previews 等) | アプリ表示 |
|---|---|---|
| 展示タイム | exhibition_time | 要確認 |
| チルト | tilt_adjustment | 要確認 |
| スタート展示 進入/ST | course_number / start_timing_exhibition | 要確認 |
| 天候 | weather_number | 一部表示 |
| 気温 | temperature | 要確認 |
| 風速 | wind_speed | **欠落確認済** |
| 風向 | wind_direction_number | 要確認 |
| 水温 | water_temperature | **欠落確認済** |
| 波高 | wave_height | 要確認 |
| 部品交換 | (stable_plate 等) | 要確認 |

洗い出し結果を作業ログに表で記録。**戸田2R(`20260816-02-02`)を再現ケース**に使える
(DBにデータ有り・公式に表示有り)。

### 2. キャッシュ再生成の不完全さを直す

- レース詳細ページ/タグの再生成が、**直前データ到着後に天候・水面コンディション・
  展示を完全に含む**ようにする。原因を特定して直す。疑わしい箇所:
  - `race.html` の compat_analysis.water ブロックが出る条件 (weather 到着後に埋まるか)。
  - `_race_current_conditions_cached` / `_venue_environment_*` / tags 再計算のいずれかが
    古い値を返している、または再計算がトリガーされていない。
  - `scripts/refresh_race_detail_after_exhibition.py::_due_races` が page cache の鮮度しか
    見ておらず、必要な再計算 (tags/conditions) を伴っていない可能性。
- **原則: DB にデータがあるのに表示されない、を解消**。到着後 (次の該当 cron tick 内で)
  ページが完全な直前情報付きで再生成されること。

### 3. トップ会場チップ (任意・軽微なら)

トップの会場別 天候/風/波チップ (`index.html` の `environment.*_label`) について、
**データがある会場は必ず表示**されるか確認。データが無い会場(発走が先)は空で正しい。
「データがあるのに空」があれば直す。無ければ作業ログにその旨。

## テスト (`tests/` に追加)

- 直前データ(weather/wind/water_temp/exhibition)が揃った race について、
  生成されるレース詳細に**それら全項目が含まれる**ことを固定フィクスチャで検証
  (戸田2R相当の入力で、風速・水温・展示タイムが出力に出る)。
- 直前データ未到着の race では、天候欄が空でもエラーにならず穏当に表示される。
- (キャッシュ再生成を直した場合) 古いキャッシュ + 新データ → 再生成で全項目が入る。
