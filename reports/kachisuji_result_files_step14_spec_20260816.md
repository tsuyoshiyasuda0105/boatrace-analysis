# 勝ち筋サーチ Step 14 仕様書 — 公式競走成績ファイルの不足分取得

作成: 2026-08-16 リン（Claude Code）/ 発注先: Codex
前提: Step 13（5958d6b）で事故履歴の復元基盤が完成。ただし成績ファイル自体が欠損しており、
2025年以降の事故データが不完全（2025年 充足82% / 2026年 46%）。

## 目的

`data/raw/results/` に欠けている公式競走成績ファイル（K ファイル）を追加取得し、
事故履歴の復元を完全にする。

## 調査済みの事実

- 不足日数: **325日**（2025-07-01 〜 2026-08-16）
- 月別内訳: 2025-07:31, 08:31, 09:30, 10:31, 11:30, 12:31,
  2026-01:31, 02:28, 03:31, 04:30, 07:7, 08:14
  （2026-05, 06 は取得済み）
- 既存の取得基盤: `src/collectors/official_dl.py::download_lzh(kind, target_date, force)`
  と `scripts/backfill_official.py`（`--start/--end/--skip-existing/--verbose/--log-file`）
- レート制限: `src/collectors/_http.py` の共有リミッタ **REQUEST_INTERVAL_SECONDS = 2.0秒**

## 絶対的な制約（違反禁止・スクレイピング規約が最優先）

1. **既存の取得基盤をそのまま使う**。`official_dl.py` / `_http.py` のレート制限を
   **緩めたり迂回したりしない**。並列ダウンロード禁止（キューは1本）。
   2.0秒間隔を必ず守ること。325日分 × 2秒 ＝ 最低でも約11分かかるのが正常。
2. **`--skip-existing` 相当の挙動を必須**とし、既に存在するファイルを再取得しない。
   既存ファイルの上書き・削除を行わない。
3. 取得対象は **K（競走成績）ファイルのみ**。B（番組表）は対象外。
4. 取得失敗（404 等、開催がない日を含む）は**エラーとせず記録して次へ進む**。
   最後に「取得成功 / スキップ（既存）/ 取得不可（理由別）」の集計を出す。
   **存在しない日を無理に取りに行って再試行を繰り返さない**（1日あたり最大1リトライまで）。
5. **DB への投入は行わない**。今回はファイル取得のみ。
   `data/boatrace.db` への書込み禁止。`racer_accident_period_stats` にも触れない。
   （事故履歴の復元と検索テーブル再生成はリンが後で実行する）
6. デプロイ・スケジューラ登録・push 禁止。実サーバー起動禁止。
7. コミットは main へのローカルコミット1つ。
   メッセージ: `Add missing official result file fetcher (kachisuji step 14)`。
   **取得したデータファイル（data/raw/results/*.lzh）はコミットに含めない**
   （.gitignore 済みのはず。含まれそうならステージしないこと）。

## 実装内容

新規 `scripts/fetch_missing_results.py`:

```
python scripts/fetch_missing_results.py --scan                       # 不足日を一覧表示（取得しない）
python scripts/fetch_missing_results.py --from 2025-07-01 --to 2025-12-31
python scripts/fetch_missing_results.py --from 2025-07-01 --to 2026-08-16 --limit 50
```

- `--scan`: `data/raw/results/` を走査し、指定期間（既定は2016-06-01〜今日）の
  不足日を列挙する。**取得は行わない**。月別サマリも出す。
- 取得モード: 不足日だけを日付昇順で `official_dl.download_lzh('K', date)` に渡す。
  - 既存ファイルがある日はスキップ（ダウンロードしない）
  - 各日の結果を `ok / skip_existing / not_found / error` に分類して集計
  - **進捗を10件ごとに出力**（残り件数と推定残り時間も出す）
  - `--limit N` で1回の実行件数に上限を設けられる（中断・再開しやすくするため）
- ログは UTF-8。`--log-file` オプションを設ける（プロジェクト慣習）。
- **User-Agent は既存の `config.USER_AGENT` を使う**（連絡先入りのもの）。変更しない。

## テスト（`tests/test_fetch_missing_results.py`）

ネットワークを使わないこと。`download_lzh` をモックして:
1. 不足日の検出が正しい（TXT / lzh どちらかがあれば「あり」と判定）
2. 既存日をダウンロードしようとしない
3. `not_found` を返す日でも処理が止まらず、集計に反映される
4. `--limit` が効く
5. `--scan` がダウンロードを一切呼ばない
6. 日付昇順で処理される
