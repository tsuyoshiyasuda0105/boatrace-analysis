作成: 2026-08-16 リン（Claude Code）/ 発注先: Codex

## 目的

艇別条件の「選手」を、番号だけでなく**名前で検索して選べる**ようにする。
「峰」と入力したら候補（峰竜太、赤峰和也 等）が出て、選ぶと選手番号がセットされる。
ユーザー決定: **姓・名・フルネーム・カナ、どの部分一致でもヒットさせる。**

## 確認済みの事実（調査根拠）

- `data/boatrace.db` の `racers` テーブルに 1,643人分:
  `racer_number, name, name_kana`（例: 4320 / 峰竜太 / ﾐﾈ ﾘｭｳﾀ）
- カナは半角カタカナ。「峰」で name 部分一致 → 6人ヒットを確認済み。
- 検索DB `data/kachisuji_search.db` には**選手名マスタが無い**（`bN_racer_id` のみ）。
- 現在のUI: 各艇の「選手」欄はテキスト入力で、番号のみ対応（名前入力は400エラー）。

## 実装内容

### 1. 選手名マスタを検索DBに複製
- `data/kachisuji_search.db` に新規テーブル:
  ```sql
  CREATE TABLE IF NOT EXISTS racers (
    racer_number INTEGER PRIMARY KEY,
    name TEXT,
    name_kana TEXT
  );
  ```
- `data/boatrace.db.racers` から `racer_number, name, name_kana` を読み取って投入する
  （読み取り専用でソースを開く）。CLI か既存の同期処理に組み込む。
  **投入方法（新規スクリプト or asof_builder の一部）を結果レポートに明記。**
- カナ検索用に、name_kana から**濁点・半角スペースを除いた正規化カナ**も検索対象にできると尚可
  （任意。実装するなら方法を明記）。

### 2. 選手検索API（app.py）
- `GET /api/racers?q=峰&limit=15`
  - `q` を name / name_kana に対する**部分一致**で検索（姓・名・フルネーム・カナのどこでも）
  - カナ入力（ひらがな/カタカナ、半角/全角）もヒットするよう正規化して比較
    （最低でも name の部分一致は必須。カナ対応の程度は結果レポートに明記）
  - レスポンス: `[{"racer_number": 4320, "name": "峰竜太", "name_kana": "ﾐﾈ ﾘｭｳﾀ"}, ...]`
  - `limit` 既定15、最大50。SQLはパラメータバインド（インジェクション不可）。
  - 2文字未満の `q` は空配列（過剰ヒット防止）。
- 読み取り専用接続（`mode=ro`）。

### 3. UI（各艇の選手欄）
- 現在のテキスト入力を、**サジェスト（オートコンプリート）付き**にする:
  - 入力するとデバウンス（250ms程度）して `/api/racers?q=...` を呼ぶ
  - 候補リストを入力欄の下にドロップダウン表示（名前＋番号）
  - 候補をクリック/キーボードで選ぶと、その艇の選手番号が確定してセットされる
  - 表示は「峰竜太 (4320)」のように名前主体。内部的には racer_number を条件に使う
  - 番号を直接入力しても従来どおり動く（後方互換）
  - キーボード操作（↑↓で移動・Enterで確定・Escで閉じる）とアクセシビリティ属性
    （`role="listbox"` / `aria-expanded` 等）を付ける
- 選手が確定している艇は、条件サマリ（Step 16）にも名前で出る
  （例「選手: 峰竜太(4320)」）。Step 16 のサマリ生成と整合させる。
- 既存の `datalist` を使った簡易サジェストがあれば置き換える。

### 4. 検索条件としての扱い
- 条件JSONの艇別 `racer_id`（数値）は現状のまま。UIが名前→番号に変換して渡す。
  **サーバーの検索ロジック（roi_search）は変更不要**（racer_id で既に検索できる）。
  変更が必要なら理由を明記。

## テスト

6. 番号直接入力の後方互換。
