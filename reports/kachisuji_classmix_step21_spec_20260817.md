# 勝ち筋サーチ Step 21 仕様書 — 級別構成の区分を整理しUIと一致させる

作成: 2026-08-17 リン（Claude Code）/ 発注先: Codex
前提: Step 20（2dbc2b9）完了。schema v9。
Round2バグチェックの注意フラグ②: UIの「A1が2人以上」がデータに存在せず常に n=0。

## 問題の実態（調査済み）

- **UIの選択肢**: 「1号艇のみA1（A1単騎）」/「1号艇A1」/「A1が2人以上」
- **データの区分（`class_mix`）**: `1号艇A1` / `A1単騎` / `A1複数_1号艇非A1` / `A1なし` / NULL
- **ズレ**: UIが送る `A1が2人以上` はデータに存在せず常に n=0。
- さらに**データ区分の命名が紛らわしい**:
  - `A1単騎` = 内部的には「A1が1人だけ、かつそれが1号艇でない」（直感と逆）
  - `1号艇A1` = 「1号艇がA1」だが**単独A1か複数A1かを区別していない**
  → 「1号艇だけがA1（最強の本命）」という重要な条件が現状**表現できない**。

## ユーザー決定

級別構成を「進めて」の指示に基づき、**区分を直感的な4分類に再設計し、UIと完全一致させる**。

## 新しい区分（4分類・排他・全網羅）

`class_mix` を以下に再定義する（レース内6艇の級別から判定）:

| 値 | 意味 |
|---|---|
| `1号艇A1・単騎` | 1号艇がA1で、レース内のA1がその1人だけ（最強の本命型） |
| `1号艇A1・複数` | 1号艇がA1だが、他にもA1がいる（拮抗） |
| `1号艇非A1・A1あり` | 1号艇はA1でないが、レース内に他のA1がいる |
| `A1なし` | レース内にA1が一人もいない |
| NULL | 6艇の級別が揃わない/欠測 |

- 判定は既存 `_class_mix`（asof_builder.py:909）を書き換える。6艇の class_number から:
  - A1の艇集合を求める
  - 1号艇がA1か / A1の人数が1か2以上か で上記4分類に振る
- **as-of厳守**: 級別は番組表（前日確定）の値を使う。当日情報は使わない（現状どおり）。

## UIの選択肢（データと1対1一致）

```
指定なし
1号艇A1・単騎（1号艇だけがA1）
1号艇A1・複数（1号艇A1＋他にもA1）
1号艇はA1でない（他にA1あり）
A1なし
```
- value属性は上記データ値と完全一致させる（phantom値を作らない）。
- 「1号艇A1（単騎・複数どちらも）」のまとめ選択は今回は入れない（将来課題として明記）。
  ※必要なら条件JSONで class_mix を配列(OR)受付にする拡張が要るが、本ステップの範囲外。
