# 勝ち筋サーチ Step 19 仕様書 — 決まり手率を「進入コース時の率」に修正

作成: 2026-08-16 リン（Claude Code）/ 発注先: Codex
前提: Step 18 まで実装済み（最新 26ea21b）。schema v7 / 557,617行。

## 背景（不具合の内容）

現行の決まり手率 `bN_kimarite_rate_{key}` は「**その決まり手での1着回数 ÷ 全出走回数**」で
計算されている。そのため 1号艇の逃げ率でも平均9.2%・最大50%にしかならず、
ユーザーが期待する「1コースに入ったときの逃げ率（A1で60〜70%が普通）」と一致しない。
「逃げ率65%以上」で0件になるのはこのため。**未来情報は使っておらず（検証済み）、定義の問題。**

## 正しい定義（ユーザーの実用感覚 = 日和等の「逃げ率」に合わせる）

決まり手率は「**その決まり手が発生しうるコースに進入したときの、当該決まり手での1着率**」とする:
- 逃げ（nige）: **1コース進入時**の「逃げ1着 ÷ 1コース進入回数」
- 差し（sashi）/ まくり（makuri）/ まくり差し（makurizashi）: その選手が該当コースに入ったときの率。
  ただしコースと決まり手の対応が一意でないもの（差し・まくり等は2〜6コースで起こりうる）は、
  **「2〜6コース進入時（＝非1コース進入時）の当該決まり手1着率」**とする。判断基準を docstring に明記。
- 実装がシンプルになるなら、全決まり手を「**その決まり手で実際に1着になった回数 ÷ 有効進入回数**」とし、
  分母の「有効進入」を決まり手ごとに定義する方式でよい。**採用した分母定義を結果レポートに明記。**
- 進入コースのデータは `start_timing_events.course_number`（336万件、1コース56万件）を使う。
  ※展示進入ではなく**実際の進入コース**（成績ファイル由来、レース後に確定するが、
  これは過去レースの集計材料であり、対象レース当日以降は使わない＝as-of厳守なので問題ない）。

## 実装内容

### 1. 進入コース×決まり手の履歴集計
- 選手ごとに「進入コース別の出走数」と「進入コース別・決まり手別の1着数」を、
  `start_timing_events`（進入コース）と `race_results`（決まり手・着順）から集計できるようにする。
  - 既存の事故/ST復元と**同じ成績ファイル・同じパース経路**を使えるなら統合する（二重パース回避）。
  - `start_timing_events` に決まり手が無ければ、`race_results.kimarite` と結合して取得。
- as-of: レース前日までの窓（既存の決まり手と同じ窓定義。180日か365日か、現行に合わせる。
  現行窓を確認して踏襲し、結果レポートに明記）。

### 2. 決まり手率の再定義（asof_builder, schema v8）
- `bN_kimarite_rate_nige` = 前日まで窓の「1コース進入時の逃げ1着数 ÷ 1コース進入回数」×100
- `bN_kimarite_rate_sashi` 等 = 上記「正しい定義」に従う
- **有効進入回数が一定未満（例: 該当コース進入 < 10回）なら NULL**（母数不足で率が暴れるため）。
  併せて `bN_kimarite_n_nige` 等の有効進入回数を持つか、少なくとも NULL 判定に使う。
  持たせるかは判断し結果レポートに明記。
- 進入0回なら NULL（0にしない）。
- 参考: A1級1号艇の逃げ率が概ね55〜75%程度の分布に収まれば定義は妥当（サンプルで確認）。

### 3. UI
- 決まり手条件のラベルを「決まり手 勝率（進入コース時）」等、定義が伝わる表記に更新。
- 補足文: 「1コースに入ったときの逃げ率など、そのコースに入ったときの決まり手成功率です」。
