# 勝ち筋サーチ Step 12 実装仕様書 — オッズ条件の撤去（ユーザー決定）

作成: 2026-08-16 リン（Claude Code）/ 発注先: Codex
前提: Step 11 まで実装済み（最新 af95658）。

## ユーザー決定（理由つき）

**オッズによる絞り込み条件を全面的に不採用とする。**

理由（ユーザーとリンで確認済み）:
- 回収率は「条件に合う全レース（当たり外れ問わず）」を分母にして初めて正しく出る
- 買い目の払戻オッズは「実際に来た組番」にしか存在しないため、これで絞ると分母から外れが消え、
  回収率が異常膨張する（例: 大村3連単1-2-3 → 正=81.1% / 誤=938.6%）
- T-5min の人気帯（`t5_odds_favorite`）も、締切前にしか意味がなく、
  現状は混乱の元になるため今回は撤去する

したがって **UI・条件JSON・照合からオッズ条件を取り除く**。
ただしデータ（odds_snapshot テーブル・t5_odds_favorite 列）は将来のために**残す**。

## 変更内容

### 1. 検索エンジン（roi_search.py）
- 条件JSON の `odds`（買い目オッズ帯）と `t5_odds_favorite`（人気帯）の**両方を廃止**する。
- これらのキーが指定された場合は、未知キーとして**日本語エラーで 400**
  （例:「オッズによる絞り込みは廃止されました。回収率は条件に合う全レースを分母に計算します」）。
  ホワイトリスト検証で自然に弾かれるならそれでよいが、**専用の分かりやすいメッセージ**を返すこと。
- オッズ用の JOIN 処理は削除してよい（デッドコードを残さない）。ただし `odds_snapshot`
  テーブル自体は参照しなくなるだけで、削除・DDL は行わない。

### 2. 照合（strategies.py）
- オッズ関連の pending 判定・`undetermined_columns` から `odds` / `t5_odds_favorite` を除去。
- 過去に保存された手法に `odds` / `t5_odds_favorite` 条件が含まれる場合:
  一覧には残すが、**再検索・照合時は上記の日本語エラーで拒否**し、
  画面に「この手法はオッズ条件を含むため実行できません。条件を編集してください」と案内する。
  （Step 8 で `final` 手法に対して行った扱いと同じ方針でよい。実装方針は結果レポートに明記）

### 3. 画面（search.html / css）
- レース条件セクションから**オッズ関連の入力UI・説明文・バッジをすべて削除**する。
- 削除後にレイアウトが崩れないこと（空セクションが残らない）。
- 凡例（legendbar）からオッズに関する記述を削除。

### 4. ドキュメント
- 結果レポートに「なぜオッズ条件を廃止したか」を1段落で記載
  （分母が壊れる問題。将来 T-5min を事前絞り込みとして復活させる余地は残す旨）。

## テスト

1. 条件JSON に `odds` を含めると 400 + 日本語メッセージ
2. 条件JSON に `t5_odds_favorite` を含めると 400 + 日本語メッセージ
3. オッズ条件を含む保存済み手法の一覧取得は成功するが、`/matches` と成績計算は 400 で拒否され案内が返る

5. E2E: 画面にオッズ入力UIが存在しない（セレクタ・ラベル文言の不在を確認）
6. 既存の全テスト（ユニット187 + E2E 56）がグリーン
