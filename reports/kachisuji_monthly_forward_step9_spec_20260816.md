## 1. 月別内訳

### 1-1. エンジン（roi_search.py）
- 返却JSONに `monthly` を追加。形式:
```json
"monthly": [
  {"year": 2025, "month": 1, "n": 12, "hits": 2, "roi": 143.3},
  {"year": 2025, "month": 3, "n": 8,  "hits": 0, "roi": 0.0}
]
```
- **データがある年月のみ**（該当0件の月は含めない）。`yearly` と整合すること
  （各年の月別 n 合計 == その年の yearly n）。
- 既存の `yearly` は変更しない（後方互換）。
- 性能: 既存の年別集計と同じ1パスで month も集計する（追加クエリで往復させない）。

### 1-2. 画面
- 年別テーブルの各行の左に「＋」ボタン（アクセシブルに: `aria-expanded`, `aria-controls`, キーボード操作可）。
- クリックでその年の月別行を直下に展開/折りたたみ（複数年を同時に開ける）。
- 月別行は視覚的に一段インデントし、年行と区別する。列は 年月 / N / 的中 / 回収率。
- 回収率は既存と同じ配色ルール（100%以上=良、未満=悪）を適用。`tabular-nums` で桁を揃える。
- 月別データが1件もない年は「＋」を出さない（または disabled）。

## 2. マイ手法の実成績（本ステップの主目的）

### 2-1. 成績の定義（3種類）

| キー | 定義 |
|---|---|
| `backtest` | 保存時に記録済みの探索時成績（`strategies.backtest_json`。無ければ null） |
| `overall` | 保存された条件で**現在の全期間**を再検索した結果（条件内の date_from/date_to は無視して全期間） |
| `forward` | 保存された条件を **`created_at` の日付（JST）より後のレースに限定**して再検索した結果 |

- `forward` の起点: `created_at` を JST 日付に変換し、**その翌日以降**を対象
  （保存当日のレースは保存時点で結果が出ていた可能性があるため除外する。安全側）。
  この規約を docstring と結果レポートに明記すること。
- `overall` / `forward` とも、既存の `search_roi` を**再利用**して計算する（ロジック再実装禁止）。
- CI は既定で高速版（正規近似 = `fast=True`）を使う。一覧で複数手法を計算するため。

### 2-2. 運用判定バッジ
`forward` の n と roi から判定（ユーザーの既存運用ルールに準拠）:

| 判定 | 条件 | 表示 |
|---|---|---|
| `promote` | n >= 30 かつ roi >= 130 | 🟢 昇格候補 |
| `watch` | n >= 30 かつ 70 <= roi < 130 | ⚪ 監視中 |
| `demote` | n >= 30 かつ roi < 70 | 🔴 降格候補 |
| `pending` | n < 30 | 🟡 判定待ち（あと N 件） |

- `pending` のときは「判定にはあと ○件」を計算して返す（30 - n）。
- 判定は API 側で行い、`verdict` と `verdict_label` を返す（画面で条件分岐を再実装しない）。

### 2-3. フォワード累積収支
- `forward` の対象レースについて、日付順の**累積損益（100円固定）**を配列で返す:
```json
"forward_curve": [{"date": "2026-08-17", "cumulative": -100}, ...]
```
- 日単位で集計（同日複数レースは合算）。データが多い場合は最大200点にダウンサンプリングしてよい
  （その場合は等間隔で間引き、最初と最後は必ず含める）。
- 画面では小さなスパークライン（インラインSVG）で表示。0ラインを破線、終点を強調。
  プラス終了なら良色、マイナスなら悪色。

### 2-4. API
- `GET /api/strategies/<id>/performance` — 単一手法の3成績＋判定＋カーブを返す:
```json
{
  "strategy_id": 1, "name": "...", "created_at": "...",
  "days_since_saved": 30,
  "backtest": {"roi": 226.0, "n": 30} | null,
  "overall": {"roi": 93.5, "n": 1176, "hits": 91, "roi_ci_low": .., "roi_ci_high": ..},
  "forward": {"roi": 118.2, "n": 42, "hits": 5, "roi_ci_low": .., "roi_ci_high": ..},
  "verdict": "pending", "verdict_label": "判定待ち", "races_until_verdict": 0,
  "forward_curve": [...]
}
```
- `GET /api/strategies/performance` — **全有効手法**をまとめて返す（一覧表示用の配列）。
  手法数が多い場合に備え、`forward_curve` は単一手法APIのみに含め、一覧では省略してよい
  （どちらにしたか結果レポートに明記）。
- 既存API（`/api/strategies`, `/api/strategies/<id>/matches`, `/api/matches`, `/api/search`）の
  挙動は変更しない。

### 2-5. 画面（マイ手法セクション）
各手法カードに以下を表示:
- 手法名 / 保存日 / 経過日数
- 3成績を縦に並べる（ラベル: 探索時 / 全期間 / フォワード）。各行に ROI と N。
  **フォワード行を最も目立たせる**（太字・大きめ）。
- 判定バッジ（🟢🟡⚪🔴）。`pending` は「あと○件で判定」も表示。
- フォワード累積収支のスパークライン。
- **注意書き**（常時表示、小さく）:
  「フォワードは保存日以降のレースだけで集計した成績です。探索時の数値は上振れを含むため、
   実力に近いのはフォワードです。判定はN30以上から。」
- 成績計算は一覧表示時に自動実行（手法数が多いと遅くなる場合は、
  各カードに「成績を見る」ボタンを置いて個別取得でもよい。採用方針を結果レポートに明記）。

## テスト

### 月別
1. `monthly` が年月別に正しく集計され、各年の月別 n 合計が `yearly` の n と一致する
2. データのない月が含まれない
3. E2E: 年行の「＋」で月行が開閉する / aria-expanded が切り替わる

### フォワード
4. `forward` が `created_at` 翌日以降のレースのみを対象にしている
   （合成フィクスチャで保存日前後のレースを配置し、境界を厳密に検証）
5. 保存時に条件へ date_from/date_to が入っていても `overall` は全期間になる
6. 判定バッジ: n=29→pending / n=30&roi=130→promote / n=30&roi=129.9→watch /
   n=30&roi=69.9→demote の境界を検証
7. `forward_curve` の累積が日付順に正しく積み上がる。ダウンサンプル時も最初と最後を含む
8. フォワード対象が0件のとき（保存直後）でも例外にならず n=0 / pending を返す
9. E2E: マイ手法カードに3成績・バッジ・スパークラインが表示される
10. 既存の全テスト（ユニット + E2E）がグリーン
